# 排谱、播放页与整片渲染

## 排谱（`demo/build_score.py`）

用 Verovio 把选定范围排成**单行**超长 SVG，导出每个音符的时间表和控制事件（力度、文字、渐强线等）所属的声部，再用对齐结果把谱面时间换成录音时间，写入 `demo/build/data.js`。

- 有 `scores_fixed/` 的副本就用副本。
- 社区谱里没修完的占位字只在排谱前于内存中去掉，副本不变。
- 文字里的乐谱字体私有区字符（如 U+ECA5）排谱时去掉，否则显示成方框。
- **Verovio 的坑**：某些竖琴琶音记号（arpeggiate）会让整份横向排版失败，页面宽 500、高二十多亿单位，所有音符拿到哨兵坐标（−33554430），谱面一片空白。排完检查页面宽高，异常就去掉琶音记号重排，仍异常再去掉圆滑线。
- 播放页定位时，横坐标是哨兵值的音符不作锚点；锚点取"横坐标不减的最长子序列"，不要把横坐标强制取到目前为止的最大值（一个离群点就会让后面全部卡住）。

## 播放页（`demo/player.html`）

`renderAt(t)` 画出任意时刻的一帧，与前后帧无关，所以可以从任何一帧开始渲。

- **播放线固定，谱面移动。** "时刻 → 横坐标"在 0.25 秒高斯窗里平滑，密集处不卡。
- **染红**：正在发声的音符整个变红（符头、符干、符尾、变音记号、附点、奏法记号）；发声前 30 毫秒开始变、发声后 20 毫秒全红，约 0.12 秒渐变恢复。符杠、延音线、两音颤音的横杠只把播放线扫过的部分标红。圆滑线不染。
- **只显示正在演奏的声部**：声部的音符进入画面右缘前淡入、最后一个音离开左缘后淡出；一小节内先后进出的声部成组进出；淡入淡出 0.18–0.7 秒，随起音密度和拍长变化。
- **全奏时整体缩小**（像镜头拉远，下限 0.45 倍），不分割谱面。
- **固定谱头**：左缘钉着每个在场声部的谱号和调号，谱号按时刻更换。
- **比一小节长的渐强、渐弱线不画**：长线容易和长延音线叠在一起，必要时在解析卡里讲。社区谱有些没写终点，Verovio 会一直画到行尾。
- 离谱表太远的渐强渐弱线挪回谱表下方，否则压紧行距后会落到下一行谱表上。
- 排练记号不画（数据仍保留作段落路标）。跨两行的竖琴滑奏线不画。
- **性能**：只更新视口附近的小节；属性值没变就不写。密集段原来每帧上万次 DOM 写入（0.2 帧/秒），改后约 5 帧/秒，画面逐像素一致。
- **视口外的小节要从 DOM 摘下，不能只设 `display:none`。** 大乐章整乐章排成一行时元素可达百万级（马勒六终乐章 119 万个），隐藏的元素仍在树里，浏览器每帧照样要处理，4K 下截图一帧 614 毫秒、每进程 0.7 帧/秒；摘下（原位留注释节点作占位，回到视口附近时插回）后 125 毫秒、每进程约 6 帧/秒，逐像素比对只有 ≤2/255 的抗锯齿噪声。显卡绘制（`EDGE_GPU=1`）对此没有帮助。
- **先拆开计时再优化。** 用 DevTools 的 `Performance.getMetrics`（脚本、样式、排版、任务累计时长）加上截图墙钟时间，把一帧拆开看；再用"只排一小段"的同一乐章对照，就能判断慢是来自分辨率、内容本身还是 DOM 规模。
- 乐章之间的过渡（7 秒）：下一乐章标题单独出现在谱面区正中，消失后整份谱面连同谱号从右缘外流入，t=0 时速度正好等于正常滚动速度。时长常量在文件开头，`window.INTRO_SEC` 供渲染脚本读取。

## 单段试片（`demo/render_frames.py`）

只用 Python 标准库，通过 DevTools 协议驱动无头 Edge 逐帧截图，交 ffmpeg 合成，并把对应的录音合进来。可续跑：页面或数据一改，旧帧自动作废。`--port` 换调试端口，可以在长渲染进行时另外截检查图。

## 整片（`demo/render_film.py`）

```
plan   → film/plan.json、film/plan_settings.json（分辨率、帧率、成片名、声音来源）
worker → 领一段、渲一段；可同时起多个
status → 进度
assemble → 拼画面、做声音、写章节
```

关键设计：
- **每个连续段只排一次谱。** 一个乐章（有反复跳转的按跳转切开）只排一份谱，多个进程按帧号分段共用它。实测直接渲某一帧与连续渲到该帧只差几十个像素的抗锯齿（肉眼不可见），所以接缝无痕。早期每段单独排谱，接缝处行距、缩放会跳。
- `--single 4`：让某个乐章只由一个进程从头渲到尾；配合 `film/hold_m<N>` 标记（普通 worker 跳过）和 `worker N --only <乐章>`。
- 设备缩放：版面按 1920×1080 设计，`deviceScaleFactor = W/1920` 直接出 2560×1440 或 3840×2160。
- 截图（JPEG 质量 95）经管道直接交 ffmpeg，不落地存帧。编码用 NVENC：`h264_nvenc -profile:v high -rc constqp -qp 17`，**统一标成 tv（标准）色彩范围**。混用不同编码器（如前 20 分钟 AMF、之后 NVENC）会让部分系统播放器在中途出错。
- 声音最后按乐章从录音整段截取，避免分段接缝。`--audio mkv` 从完整演出视频的原始音轨（FLAC 48 kHz / 24 位）按偏移截取，成片封装为 .mkv、FLAC 24 位；否则从各乐章音轨截取，成片 .mp4、AAC。
- 乐章之间的静音 = 上一乐章结尾留白（谱面滚出）+ 下一乐章开场过渡。
- 片头（`cover.html`）、片尾参考资料（`credits.html`，内容超出一屏时缓慢上卷）用同一套截图流程。

速度参考（Ryzen 7 8 核、16 GB 内存、RTX 5060，同时跑 3 个进程，DOM 摘下之后）：4K 每进程约 6 帧/秒。整乐章页面每个约占 4 GB 内存，内存是能同时开几个进程的上限。
