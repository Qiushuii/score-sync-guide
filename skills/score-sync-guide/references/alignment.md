# 谱面与录音对齐

目标：得到"谱面位置（四分音符数 q）→ 录音秒数"的单调映射。

## 推荐顺序（少走弯路）

```
① 逐小节 DTW（align.py）          粗定位：每小节的起点，开头用人工锚点、结尾用子序列对齐
② 逐起音细对齐（ssv_align.py）     score-sync-video 的算法，以 ① 为引导，一次解决大部分小节内的偏移
③ 听检（make_disputes.py）         对着谱面听，只记下 ② 之后仍然不对的地方
④ 人工钉点 / 局部重校              只修 ③ 里剩下的错误
⑤ 重跑 ②                          钉点作为精确约束交给细对齐，其余起音自动跟着调整
```

**先细对齐、后钉点。** 我们当初的顺序反过来：先在逐小节结果上听了八轮、加了近百个钉点和拍点，最后才引入逐起音细对齐，结果它一次就解决了大部分"小节内差一点"的问题（用户的原话："能省一大堆精力和额度去描述错误"）。钉点只在细对齐之后还错的地方才值得加。

> 说明：上面的推荐顺序是事后根据经验调整的，我们没有按这个顺序从头完整走过一遍。

---

## ① 逐小节 DTW（`align/align.py`）

- **特征**：谱面按实际音高画模板（基音 + 第 3、5 泛音，音符结束后约 1 秒衰减的余响），与录音的 CQT 色度比较，外加起音包络。
- **两遍 DTW**：粗对齐约 4.8 帧/秒，再在粗结果 ±1.5 秒的带子里做精对齐，约 43 帧/秒。原地踏步每步加罚。
- **开头用人工锚点**（`align/anchors.json`，±0.05–0.1 秒）。这是唯一建议一开始就人工给的东西：只按响度硬定起点、或让起点完全自由，都会对错。弱起、第一拍是休止、开头就有噪声，三种情况我们都遇到过。
- **结尾用子序列对齐**：谱面末帧可以对到录音最后 90 秒内任一帧；终点之后的录音按响度付"跳过代价"，掌声被跳过，弱奏的尾声不会被跳过。
- 粗对齐不要用 librosa 自带的子序列 DTW：它允许跳过录音不花代价，曾把一个乐章开头两分钟整段跳过。
- 输出 `m<N>_measures.json`（每小节 `q_start`、`audio_sec`、实际速度、`flags`）、`_check.wav`（小节线处"嗒"）、`_path.png`，以及低置信度小节的听检清单（`make_checklist.py`）。

## ② 逐起音细对齐（`align/ssv_align.py`，算法来自 score-sync-video）

借用 [tofucurd/score-sync-video](https://github.com/tofucurd/score-sync-video)（MIT）的函数，原样复制在 `align/vendor_ssv/`：

- `dense_sequence`：10 毫秒网格上的"状态 + 起音"带状 DTW，谱面每步 1/64–1/128 拍，局部速度 0.4–2.5 倍；
- `correct_guide` + `refine_attack_chain`：逐起音在录音里找候选峰（±2 秒），相邻间隔偏离附近速度的罚 4·ln²，整条起音链一起求最优。

我们的接法：**引导路线用 ① 的逐小节结果；钉点、小节内拍点、起点锚点（有的话）全部当精确约束**（容差 15 毫秒）。还没有钉点时直接跑即可。输出 `m<N>_ssv_chain.json`（逐起音 q → 秒），`build_score.py` 自动读它代替"小节内匀速"。

- 时间表记有输入指纹（小节表 + 本乐章的钉点与锚点）。**改了小节表或钉点后要重跑**，否则 `build_score.py` 报错停下，不会悄悄用过期结果。
- `align/ssv_eval.py` 用 librosa 通用起音检测独立检验：在马勒六上，起音到最近录音起音的中位距离，四个乐章分别从 68/85/46/96 毫秒降到 51/46/37/84 毫秒。少数小节会被挪 1–3 秒，要听。
- 拿不准时做 A/B：同一段先旧后新各渲一遍给用户听。我们四个乐章都选了新法。

## ③ 听检

- **争议片段合集**（`demo/make_disputes.py`）：把每段低置信度小节（前带 2 小节、后带 1 小节）渲成带谱面、带录音的短片，开头静止 1 秒，右栏写明乐章、小节、录音时刻和可疑原因，拼成一支带章节的视频。用户不识谱也能听出"画面上的音和听到的不是一回事"。**对着谱面听比听"嗒"声可靠得多。**
- **用户的话换算成钉点**："合集里 v1 时刻谱面上的内容，在 v2 才听到"：查出所在章节起点（`ffprobe -show_chapters`）与片段首行的录音时刻，`rows[k0].audio_sec + (v − 章节起点 − 1)` 就是该内容的真实录音时刻。
- 听感上"变红略早一点"多半来自感知起音（P-center）晚于物理起点，算法定不了；播放页有全局延后量 `&delay=毫秒`。
- 自动的按声部音高复核（`pitch_check.py`）在织体密的地方不可靠；`entry_check.py` 只看旋律线上新进入的音，可靠得多，可以用它给候选钉点。

## ④ 人工钉点与局部重校（`align/manual_regions.json`、`align/refine_local.py`）

- `pins`：钉点（对齐表行号 → 秒）；`beats`：小节内拍点 `[[q, 秒], …]`，用于小节内速度很不均匀的地方；`rows`：强制重校的段；`end`：最后一小节结束时刻。
- `refine_local.py` 在每个可疑段两侧各取 3 个小节作固定端点，只在这一小段里重新对齐，DTW 局部斜率限制在 1/3–3 倍，不插值；新代价更低才采用。钉点两侧会一起重对。
- **钉点的教训**：单个钉点可能把相邻小节挤得极短（出现过 0.1 秒的小节），这种钉点要撤回或改成均分；按"每小节一击"钉定音鼓之前先看原谱，可能是持续滚奏。

改完回到 ②，重跑细对齐。

## 试过、不推荐

| 做法 | 结果 |
|---|---|
| 可疑小节按谱面时值平均插值 | 用户听出的问题多数来自它：1 秒的小节、前后 5 秒中间 2 秒的小节、整段速度被抹平。已改为局部重校 |
| 小节内 rubato 按音高自动校准（自写） | 起音偏差中位数只变 ±2–4 毫秒，检测噪声与要校的 rubato 同一量级，无效。逐起音细对齐才真正解决 |
| "吸附"到检测到的物理起音 | 物理起点比对齐时刻还早，吸附让提示更早，与听感相反，已关闭 |
| parangonar 逐音符对齐（整乐章） | 谐谑曲（拍号频繁切换、速度起伏大）整段失败，被挤到开头；钢琴默认参数不适合管弦乐 |
| parangonar 局部精修（`refine_parangonar.py`） | 加了四道检查后才安全，但真正采用的很少；第二遍复核一个都没采用 |
| synctoolbox | 不支持 Python 3.15，装不上 |

## 拼接音频的坑

不同乐章录音采样率不同（44.1 kHz 与 48 kHz）时，ffmpeg 按第一段的格式读后面各段，后面的声音会被拉慢、与画面错开。**拼接前先把每段转成同一采样率。**我们曾因此把一整轮终乐章的听检反馈建立在错误的声音上，加的钉点全部撤回。
